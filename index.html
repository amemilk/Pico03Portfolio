01 // Project Scope

Project Overview & Architectural Modification

Baseline Specification

Single-Board Speed & Proximity Sensor

The standard Pico-3 assignment specifies mounting all sensors, indicators, and display hardware onto a single Raspberry Pi Pico board facing a stationary target such as a wall or box.

  • 01 Measure distance repeatedly with an HC-SR04 ultrasonic sensor and calculates velocity using speed = Δdistance / Δtime (cm/s).
  • 02 Illuminate a green LED when moving at or below a chosen target speed, and switch to a yellow LED when exceeding that speed threshold.
  • 03 Use an infrared obstacle avoidance module to trigger a red warning LED at close range while continuously updating distance and speed on a 16x2 LCD.
Formula: v (cm/s) = (d₂ - d₁) / (t₂ - t₁)
Professor-Approved Modification

Distributed 3-Pico UART Serial Network

Rather than wiring all sensors and the display onto one single board, the professor approved trying an alternative multi-board architecture: connecting 3 Raspberry Pi Pico boards together using hardware UART serial links at 9600 baud.

  • B1 Board 1 (Main Controller Pico): Receives two independent data streams via UART0 (GP13) and UART1 (GP9), decodes UTF-8 lines, and drives the 16x2 I2C LCD and RGB LED.
  • B2 Board 2 (IR Obstacle Node): Reads the digital output pin of the IR obstacle avoidance module and transmits "Obstacle" or "Clear" lines over UART TX to Board 1 GP13.
  • B3 Board 3 (Ultrasonic Distance Node): Transmits distance/speed strings over UART TX to Board 1 GP9.
Serial Parameters: 9600 Baud, 8-N-1, Common Ground Reference

IR Obstacle Module + UART + I2C LCD

The infrared obstacle detection operated reliably across the multi-board UART link. Board 2 sampled the IR module's digital output and transmitted clean ASCII lines at 9600 baud to GP13 on the main controller Pico, updating Row 1 between "Obstacle" and "Clear".

Unobstructed Sensor: LCD Row 1: "Clear"

UNRESOLVED SUBSYSTEM UART1 RX (GP9)

HC-SR04 Ultrasonic Distance Sensor

The HC-SR04 ultrasonic module on Board 3 sent mixed, erratic signals over UART1 RX (GP9) to the main controller Pico (rendered on Row 2 of the LCD). Because the raw readings were noisy signals, stable distance deltas (Δd) and reliable speed values (cm/s) could not be derived.

Experimental Architecture Note: Connecting 3 Pico boards over UART successfully isolated sensor tasks across separate microcontrollers, though the ultrasonic echo signal remained noisy during testing.

Observed Bench Behavior

The recording captures all three breadboards powered simultaneously while testing sensor response and UART packet delivery to the main hub LCD:

  • 1 IR Obstacle Activation: Moving a hand over the middle breadboard's IR obstacle avoidance module illuminates the sensor's blue indicator LED.
  • 2 UART0 Serial Transmission: Board 2 transmits the updated obstacle status over the 9600-baud UART link to GP13 on the top main controller Pico.
  • 3 Dual-Row LCD Updates: Row 1 of the top breadboard's 16x2 LCD toggles cleanly between Obstacle and Clear when the hand is removed, while Row 2 displays the unstable readings arriving from the ultrasonic sensor board.
Polling Interval: 100 ms Baud Rate: 9600 bps
